# Bug 修复：Web UI 部分工作区对话无响应

## 问题

- `D:/Vibecoding/Opencode_Project` → Web UI 正常
- `D:/Vibecoding/omni-agent-hub` → Web UI 发消息后有错误提示音，一直"思考"

## 根因

日志关键证据：
```
run=e6f33838 message="creating instance" directory="D:\\Vibecoding\\omni-agent-hub"
run=e6f33838 message="[feishu] 飞书插件初始化失败" error="Cannot destructure property 'tenant_access_token'..."
（重复 8 次 — Lark SDK TokenManager 内部重试）
```

**OpenCode 每次为新工作区创建实例时，都会重新调用插件工厂函数**。Lark SDK 的 TokenManager 在后台不断重试获取 token（8 次），这些后台请求可能：
1. 消耗事件循环资源，影响 agent 响应
2. 产生大量错误日志，干扰正常流程
3. 虽然插件已降级（gateway=null），但 SDK 的后台重试仍在运行

## 修复方案

### Fix 1：插件工厂函数加单例守卫（核心修复）

**文件**: `src/index.ts`

在同一 OpenCode 进程中，插件只应初始化一次。增加模块级单例标记，防止重复初始化：

```typescript
// 模块级单例守卫：同一进程内只初始化一次
let pluginInitialized = false
let cachedHooks: Hooks | null = null

export const FeishuPlugin: Plugin = async (ctx) => {
  if (pluginInitialized && cachedHooks) {
    return cachedHooks
  }
  // ... 原有初始化逻辑 ...
  // 成功后：
  pluginInitialized = true
  cachedHooks = hooks
  return hooks
}
```

### Fix 2：Lark Client 创建增加超时保护

**文件**: `src/index.ts`

在 `new Lark.Client()` 之后增加 token 预获取，失败时立即抛出（不让 SDK 后台重试阻塞）：

```typescript
larkClient = new Lark.Client({...})
// 预获取 token，失败时立即报错（不等 SDK 后台重试）
await larkClient.request({ url: '...', method: 'GET' })
```

## 关键文件

- `src/index.ts` — Fix 1 + Fix 2
